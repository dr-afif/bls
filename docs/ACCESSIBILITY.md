# Accessibility

## Target

WCAG 2.2 AA.

## General requirements

- Full keyboard navigation
- Visible focus indicators
- Semantic HTML
- Accessible names for interactive controls
- Sufficient text and control contrast
- No colour-only meaning
- Scalable text
- Reduced-motion support
- Clear error messages
- Logical heading hierarchy
- Responsive reflow
- Adequate touch targets

## Authentication

- Label every field.
- Connect validation errors to fields.
- Preserve entered values after recoverable errors.
- Provide show-password controls with accessible state.
- Avoid timeout during profile completion without warning.

## Navigation

- Provide skip navigation.
- Mark current location.
- Ensure mobile bottom navigation is screen-reader friendly.
- Ensure sidebar collapse does not trap focus.
- Restore focus after closing dialogs or sheets.

## Videos

- Captions required.
- Transcript required where practical.
- Do not communicate essential information through audio alone.
- Player controls must remain keyboard accessible.
- Provide a clear completion indicator.

## PDFs

- Prefer accessible source PDFs.
- Preserve text and reading order where possible.
- Provide alternative HTML or transcript for inaccessible documents.
- Do not disable text selection if doing so prevents assistive-technology access without an alternative.
- Ensure viewer toolbar is keyboard operable.

## Quizzes

- Do not rely on drag and drop alone.
- Provide keyboard alternatives for ordered questions.
- Announce save state.
- Announce timer warnings without excessive interruption.
- Allow approved accessibility accommodations.
- Ensure answer options have large click targets.
- Provide clear validation before submission.
- Do not use animation to indicate correctness alone.

## Time limits

Support accommodations such as:

- Additional time
- No timer
- Pause authorization
- Alternative assessment format

Accommodations must be server-enforced and audited.

## Charts

- Provide text summaries.
- Provide accessible data tables where appropriate.
- Do not rely on chart colour alone.
- Use clear labels and legends.

## Forms

- Use fieldsets and legends for grouped answers.
- Identify required fields.
- Put error summaries at the top for complex forms.
- Move focus to error summary after failed submission where appropriate.

## Testing

Include:

- Keyboard-only testing
- Screen-reader spot checks
- Automated accessibility scans
- Zoom and reflow testing
- High-contrast review
- Reduced-motion review
- Mobile accessibility testing

Automated tools do not replace manual review.
